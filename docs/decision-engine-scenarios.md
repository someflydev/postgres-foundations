# Decision Engine Scenarios

The industry scenarios under `scenarios/industries/` are both teaching cases and regression fixtures. Each scenario pack contains:

- `narrative.md`: the human case study.
- `scenario.json`: teaching metadata and expected decision outputs.
- `intake.json`: the structured decision-engine input.
- `expected-report.json` and `expected-report.md`: goldens generated by the current engine.

The set intentionally moves across scale and maturity. Early scenarios should often say "not yet" for higher-burden extensions. Mature scenarios should recommend those same tools only when the intake includes the trigger conditions: spatial predicates for PostGIS, measured time-series lifecycle pain for TimescaleDB, embedding and evaluation ownership for pgvector, bounded federation for postgres_fdw, and cutover requirements for logical replication.

Run `uv run pgfound content validate` to check scenario structure and golden drift. Run `uv run pytest -q tests/test_scenarios_*.py` for focused regression coverage.

`uv run pgfound decision scenarios audit` renders a table of every extension catalog slug and how often it appears as `recommend_now`, `candidate_later`, `not_enough_evidence`, or `avoid_for_now`. Use it during rule changes to spot tools that are over-recommended or never surfaced.
