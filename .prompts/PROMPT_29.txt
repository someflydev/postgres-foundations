PROMPT 29 — Training-side LLM prompts: coaching, critique, remediation
======================================================================

## Context

`postgres-foundations`. The platform already has a review engine
(PROMPT_27) and interview simulator (PROMPT_28) with *stubbed* LLM
calls. This prompt authors the real **training-side** LLM prompt
templates. These templates are plain Markdown files with a
light front-matter block; they are consumed by the `pgfound` CLI
which renders them against a context before sending to an LLM.

Doctrine (from `docs/llm-usage.md`):

- LLM as coach/reviewer/adversary/remediation-generator.
- LLM NOT as first-pass answer machine, SQL bypass, schema bypass,
  lab replacement, or concurrency lab replacement.
- Prompts should steer the LLM away from "give me the answer"
  behavior in contexts where self-directed struggle is the point.

### 2. Template format

Each prompt template is a Markdown file with YAML front matter:

```
---
id: critique/query-critique
title: "Critique a learner's query"
consumed_by:
  - pgfound exercise review
  - pgfound interview session
inputs:
  exercise_id: { required: true }
  learner_sql: { required: true }
  reference_sql: { required: true }
  rubric_id: { required: true }
  findings: { required: false, kind: list }
  allowed_concepts: { required: true, kind: list }
  not_yet_allowed_concepts: { required: true, kind: list }
outputs:
  format: structured-review   # references shared/output-formats/structured-review.md
model_hint: "Claude Opus or equivalent; long-context not required"
variables:
  max_feedback_items: 6
---

## System

You are a rigorous, kind, technically exact PostgreSQL coach. ...

## Context

Exercise id: {{exercise_id}}
Allowed concepts for this stage: {{allowed_concepts}}
Concepts not yet introduced (flag if used): {{not_yet_allowed_concepts}}

## Inputs

### Learner SQL
```sql
{{learner_sql}}
```

### Reference SQL
```sql
{{reference_sql}}
```

### Findings from the engine
{{findings}}

## Instructions

1. Score each rubric dimension on 0–4 with a short justification.
2. Produce up to {{max_feedback_items}} specific, actionable
   feedback items. Cite the relevant SQL fragment.
3. Identify forbidden-concept usage if any.
4. Conclude with two questions you would ask the learner at an
   oral defense.

## Output format

See {{output_format_ref}}.
```

Document this structure in `llm-prompts/template-format.md`. Also
author the shared system prompt (`shared/system-prompt-trainer.md`)
that anchors the "trainer" persona: terse, exact, refuses to
simply hand over answers; explains reasoning; prefers asking
questions back over lecturing.

### 3. Author every template listed in §1

Each template is 120–400 lines of Markdown with filled-in
system/context/instructions/output-format sections. Concrete
content notes per template:

- `coaching/concept-check.md` — given a concept slug (e.g.
  `foreign_key`) and optional lesson context, generate 3 concept-
  check questions of ascending depth. The LLM is told not to
  reveal answers.
- `coaching/analogy-generator.md` — requests two analogies
  appropriate to the learner's background, with the explicit
  caveat of naming where the analogy breaks.
- `coaching/misunderstanding-probe.md` — given a signal of
  confusion, probes with targeted questions.
- `critique/query-critique.md` — the template shown above.
- `critique/schema-critique.md` — analogous for schemas, including
  a "missing constraint census" output section.
- `critique/index-critique.md` — critiques a learner's index plan
  against a workload description.
- `critique/concurrency-critique.md` — critiques a proposed fix
  for a race drill.
- `remediation/remediation-pack-generator.md` — given a learner's
  review report, generates a short remediation pack: 2–3 reread
  lessons, 3 targeted exercises (new or existing), and one
  explainability prompt.
- `remediation/hint-ladder-generator.md` — given an exercise, a
  learner's current attempt, and their self-reported stuck point,
  produces a ladder of 4 hints from most-gentle to near-solution
  (used only for Level A/B exercises).
- `remediation/failure-lab-generator.md` — given a concept, emits
  a small failure-lab spec (new exercise, likely a Level D
  scenario) that exposes the most common mistake.

### 4. CLI integration

Add `pgfound llm render <template-id> --context <json-file> \
     [--var key=value] [--out <path>]`:

- Resolves the template by ID.
- Loads the context JSON, merges in `--var` overrides.
- Validates inputs against the template front matter.
- Renders the final prompt text with Jinja2 (add `jinja2` to
  pyproject).
- Writes to `--out` or stdout.
- Does **not** call an LLM — rendering is the contract. Actual
  LLM dispatch is a separate future concern; we want the platform
  to be LLM-provider-agnostic and to make it easy to pipe into
  a script.

Add `pgfound llm list` that walks `llm-prompts/` and prints a
table of templates with their `consumed_by` and input requirements.

### 5. Integration into existing flows

Wire these templates into the previously-stubbed flows:

- `pgfound exercise review --full` now renders
  `critique/query-critique.md` with the review engine's findings
  as input and saves the rendered prompt to the review output

- `pgfound interview start` renders the appropriate stage

- `pgfound capstone evaluate --full` renders
  `critique/schema-critique.md`, `critique/index-critique.md`,
  and a top-level "capstone-reviewer" prompt (authored in
