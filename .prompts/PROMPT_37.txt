PROMPT 37 — Extension track: E7 Citus + ltree + pg_partman + PgBouncer (deep)
=============================================================================

## Context

`postgres-foundations`. Finishing the extension track. Doctrine:

- **Citus** is explicitly late-stage. Sharding is an architectural
  commitment with serious locality implications. Most teams should
  not adopt it until they have a proven distribution key, an
  application layer that tolerates the locality model, and an
  operational team comfortable with distributed failures.
- **ltree** is narrow but occasionally exactly right.
- **pg_partman** simplifies partitioning operations; it is the
  operational counterpart to the phase-9 partitioning lessons.
- **PgBouncer** is the canonical pooler; deep ops content here
  complements the admin A3 primer.

### 2. E7 Citus — lessons

Target **10 lessons**:

1. `citus-what-it-is` — distributed Postgres; coordinator +
   workers; distributed tables; reference tables; local tables.
2. `distribution-key-discipline` — picking a distribution key that
   aligns with the workload's locality; the cost of getting it
   wrong.
3. `reference-tables-vs-distributed-tables`.
4. `co-located-joins-and-why-they-matter`.
5. `multi-tenant-via-citus` — when Citus is a good tenant-
   isolation fit vs. when plain Postgres schemas/RLS are still the
   right answer.
6. `real-time-analytics-via-citus` — the read-heavy analytics
   pattern.
7. `operational-cost-of-citus` — failover; backups; upgrades;
   the distributed-system reality.
8. `citus-on-managed-services` — Azure Cosmos DB for PostgreSQL
   is the primary managed Citus story; others are rare.
9. `moving-to-citus-from-a-single-node` — the migration cost and
   timeline honest view.
10. `when-not-to-adopt-citus` — anti-pattern explicit: sharding
    without a distribution key, sharding as "performance
    insurance", sharding to avoid having to index.

### 3. ltree — lessons

Target **5 lessons**:

1. `what-ltree-is-for` — materialized-path hierarchies with GiST;
   category trees, org charts, nested comment threads.
2. `alternatives-to-ltree` — recursive CTEs on adjacency lists;
   closure tables; when ltree wins.
3. `gist-and-gin-indexes-on-ltree`.
4. `ltree-operators` — `~`, `@>`, `<@`, `lquery`, `ltxtquery`.
5. `when-not-to-use-ltree` — most hierarchies are not deep enough
   to justify it.

4. `migrating-from-manual-partitioning`.

### 5. PgBouncer deep — lessons

Target **6 lessons**:

1. `pool-modes-revisited` — session vs transaction vs statement
   pooling; what breaks in each.
2. `pgbouncer-config-surface` — the ini; authentication modes;
   listen addresses; admin console.
3. `pgbouncer-with-scram` — the modern auth posture; how to
   pass-through.
4. `pgbouncer-and-prepared-statements` — Postgres 14+ behavior
   with transaction pooling and named prepared statements.
5. `observability-of-pgbouncer` — `SHOW` commands; exporting
   metrics.
6. `when-pgbouncer-is-not-enough` — per-backend pooling, other
   poolers (Odyssey), or moving pooling logic into the
   application.
