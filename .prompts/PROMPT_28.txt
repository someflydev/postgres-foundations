PROMPT 28 — Interview simulator scaffolding
===========================================

## Context

`postgres-foundations`. The platform has content, lab, capstones, and
a review engine. Doctrine: explanation is first-class competence. The
interview simulator is where learners practice *saying* and *defending*
their design. Without it, the platform produces people who can solve
problems but cannot ship with a team. See `docs/doctrine.md`,
`docs/llm-usage.md`.

LLM integration (real calls) lands in PROMPT_29/30; this prompt builds
the **scaffolding** that consumes those prompts — the simulator's
mechanics are real, its "interviewer voice" is still a stub that
prints the prompts it would send.

## Prior work (verify before starting)

- Review engine (PROMPT_27).
- LLM prompt templates directory `llm-prompts/` exists with
  `.gitkeep` only.

## Task

### 1. Simulator design

Implement under `src/pgfound/interview/`:

```
interview/
  scenario.py        # loads an interview scenario
  session.py         # runs a session: state machine + timing
  transcripts.py     # transcript persistence
  rubric.py          # evaluates transcript against interview rubric
  prompts.py         # LLM prompt loader (consumed by PROMPT_29/30)
```

An **interview scenario** is a YAML file under
`scenarios/interviews/`:

```
id: senior-backend-saas-rls
title: "Senior backend — multi-tenant SaaS with RLS"
duration_minutes: 45
capability_layers_required:
  - schema_literacy
  - relational_joins
  - database_truth
  - postgres_data_modeling
  - expressive_querying
  - transactions_and_correctness
  - indexing_and_plans
  - security_federation
stages:
  - kind: warmup
    prompt_template: interview/stages/warmup
    budget_minutes: 5
  - kind: design_probe
    topic: multi_tenant_rls
    prompt_template: interview/stages/design-probe
    budget_minutes: 15
  - kind: debugging_drill
    exercise_id: phase-06/races/lost-update/level-c/reproduce-lost-update
    budget_minutes: 15
  - kind: explainability
    topic: partitioning_tradeoffs
    prompt_template: interview/stages/oral-defense
    budget_minutes: 10
rubric_id: senior-backend
```

### 2. Session machine

`pgfound interview start --scenario <id>`:

- Creates a transcript file at
  `tmp/interviews/<scenario-id>/<timestamp>.md`.
- For each stage:
  - Prints the stage prompt (resolved from `prompt_template` +
    interpolated with context like the exercise prompt when
    applicable).
  - Opens a timer for `budget_minutes`. Prints remaining time
    periodically.
  - Accepts the learner's response(s) via stdin (multi-line until
    EOF or a `/next` sentinel).
  - For debugging-drill stages, hands off to
    `pgfound exercise run --check` and captures the check result.
  - For design-probe and explainability stages, the stage closes
    with a structured "follow-up questions" block pulled from the
    prompt template (the template names 3–5 standard follow-ups).
- At the end, writes the transcript and emits a review summary by
  running `interview.rubric.evaluate(transcript)`.

Every stage captures both **what the learner typed** and **what
the simulator would send to the LLM**. The LLM response is stubbed
for now: print `"[LLM response will be generated by PROMPT_29
when integrated]"`.

### 3. Interview rubric

Interview rubrics live under `rubrics/interview/`. They share the
composed-rubric schema from PROMPT_25 and emphasize dimensions
like `communication`, `decision-justification`,
`operational-awareness`, `correctness`, `tradeoff-reasoning`.
Set `applies_to: interview` on these rubrics.

Author two interview rubrics now:

- `rubrics/interview/mid-level-backend.rubric.json`
- `rubrics/interview/senior-backend.rubric.json`

Each uses interview-appropriate signal patterns (e.g. a transcript
lint looks for "because", "tradeoff", "what we might consider
later" — a weak but useful heuristic for "this person is reasoning
aloud").

Author 6 interview scenarios under `scenarios/interviews/`:

Add a dedicated schema `content-schemas/interview-scenario.schema.json` and

instead of the industry-scenario schema from PROMPT_05.

### 5. Transcript format

`tmp/interviews/<scenario-id>/<timestamp>.md` follows a strict
structure so later tooling and the review engine can consume it:

```
# Interview: <title>
- scenario_id: ...
- started_at: ...
- completed_at: ...
- learner: ...

## Stage: warmup
### Prompt
...
### Learner response
...
### Simulator notes
...

## Stage: design_probe
...
```

Parse + validate this format with a small helper in
`interview/transcripts.py`. Expose
`pgfound interview review <transcript-path>` that re-runs the
rubric against an existing transcript.

- `tests/test_interview_scenarios.py` — every interview YAML

  scripted session against a fake stdin and asserts the
