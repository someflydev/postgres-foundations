### 2. Scenario-specific posture targets

- **Logistics/geo**:
  - 01: mostly core + pg_stat_statements + GiST on a small zone
    set; PostGIS is `candidate_later`.
  - 02: PostGIS is `recommend_now`; pg_partman + BRIN on
    breadcrumbs; Timescale is `candidate_later` with specific
    triggers.
  - 03: PostGIS recommend_now; partitioning required; Timescale
    crosses into `recommend_now` for analytics workload.
- **Observability/IoT**:
  - 01: core partitioning + pg_partman + BRIN; Timescale
    `candidate_later`.
  - 02: Timescale `recommend_now`; hypertable + compression +
    continuous aggregates; justification well-grounded.
  - 03: Timescale + pgvector-for-anomaly-embedding-search as an
    intentional discussion (should be `candidate_later` with
    explicit triggers or `not_enough_evidence` — avoid hype).
- **Knowledge/AI**:
  - 01: core FTS + pg_trgm `recommend_now`; pgvector
    `candidate_later`.
  - 02: FTS + pg_trgm + pgvector `recommend_now`; hybrid retrieval.
  - 03: heavy hybrid retrieval; pgvector + FTS + pg_trgm + RLS
    for project scoping.
- **Modernization bridge**:
  - 01: postgres_fdw `recommend_now`; logical replication
    `candidate_later` with triggers; Citus blocked
    (`avoid_for_now`).
  - 02: logical replication `recommend_now`; FDW as a transition
    tool; specific migration playbook referenced.
  - 03: blue-green upgrade via logical replication pair
    `recommend_now`; pg_partman + pg_stat_statements always.

### 3. Authoring requirements

For each scenario, same as PROMPT_45:

- `narrative.md` (800–1500 words) — realistic, specific,
  judgment-demanding.
- `intake.json` — valid, slugs resolve.
- `expected-report.json` + `.md` — golden, matching engine output.
- `scenario.json` — metadata with `expected_decision_outputs`.

Emphasize **"not yet" reasoning** in each scenario's expected report.
If any scenario's report reads like "turn on every extension", the
rules need tightening — fix the rules and regenerate.

### 4. Cross-scenario coverage audit

Add `pgfound decision scenarios audit` that walks all scenarios in
`scenarios/industries/` and produces a Rich table:

- Each extension in the catalog, with counts of scenarios in which
  it lands in `recommend_now`, `candidate_later`,
  `not_enough_evidence`, `avoid_for_now`.

This gives a quick view of whether any extension is either
over-recommended or never surfacing. Use it as a reviewer tool.
