================================================================================

## Context

next serious layer of knowledge: what running Postgres actually
demands day-to-day. See `docs/doctrine.md`, `docs/architecture.md`,

### 2. A1: Roles and privileges — lessons

Target **8 lessons**:

1. `roles-vs-users` — in PostgreSQL they are the same object kind
   (`CREATE ROLE`); the NOLOGIN attribute differentiates usage.
2. `login-roles-and-group-roles` — standard pattern: `app_readwrite`
   and `app_readonly` as group roles; per-service login roles GRANTed
   into them; NOLOGIN on groups.
3. `granting-on-tables-sequences-functions-schemas` —
   the fine-grained privilege model; sequences are often forgotten;
   function EXECUTE.
4. `default-privileges` — `ALTER DEFAULT PRIVILEGES`; why it applies
   only to **future** objects and how that surprises people.
5. `membership-and-inheritance` — `SET ROLE` vs membership;
   `INHERIT` / `NOINHERIT`; `current_user` vs `session_user`.
6. `ownership-and-dependent-objects` — who owns what; `REASSIGN
   OWNED`; the chain of dependent objects.
7. `least-privilege-patterns` — real-world templates: web app role,
   migrations role, read-only BI role, break-glass admin role.
8. `auditing-privileges-and-reviewing-access` — querying
   `information_schema` and `pg_catalog` for what roles can do
   what; authoring a recurring access-review.

Every lesson ≥ 700 words. Lab examples against the saas domain
(phase-10 RLS content is a prerequisite).

### 3. A2: Schemas and databases — lessons

Target **7 lessons**:

1. `what-a-schema-is-for` — namespacing, grant boundary, search
   path interaction.
2. `schemas-vs-databases` — when to use each; why the default
   advice is "one database, many schemas".
3. `public-schema-discipline` — locking down `public`; the post-15
   behavior change where `public` no longer grants `CREATE` to
   PUBLIC.
4. `search-path-discipline` — the gotchas; how hostile an arbitrary
   `search_path` can be; per-role search_path.
5. `multi-tenant-via-schemas-vs-rls` — the schema-per-tenant
   pattern, honest comparison vs RLS, when each wins and loses.
6. `migrating-between-schemas-and-databases` — how to actually
   move data; pg_dump patterns; logical replication patterns
   (forward pointer to A6).
7. `cluster-level-management-basics` — creating and dropping
   databases; template databases; `CREATE DATABASE ... WITH` knobs
   worth knowing (`LC_COLLATE`, `LC_CTYPE`, `ENCODING`,
   `TEMPLATE`).

### 4. Exercises

Per lesson: 2A + 2B + 2C + 2D. ~120 exercises across A1+A2.

Critical drills:

- Level C: design and apply a least-privilege role matrix for the
  saas domain, including an application role, a migrations role,
  a read-only BI role, and a break-glass admin. Include an access
  review query that the learner runs afterwards.
- Level D: a leaked role audit — given a set of GRANTs dumped from
  a real (fictional) cluster, identify every over-grant and
  propose REVOKEs.
- Level D: a `public` schema with `CREATE` open to all; learner
  diagnoses and remediates.
- Level D: a search_path exploit scenario: a function owned by a
  powerful role that calls `SELECT ... FROM some_table` without
  schema qualification; a lower-privileged role injects a shim
  table. Learner proposes the fix (set search_path on the
  function definition).
