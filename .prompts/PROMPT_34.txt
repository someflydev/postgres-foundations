### 2. E1 pg_stat_statements — lessons

Target **6 lessons**:

1. `what-pg-stat-statements-actually-captures` — normalized
   queries, per-query total/mean time, I/O counters.
2. `installation-and-configuration` — `shared_preload_libraries`;
   `pg_stat_statements.max`; `track_io_timing` (pairs with pss
   for I/O analytics).
3. `reset-discipline-and-baselines` — when to reset; baseline
   approach for before/after changes.
4. `triage-patterns` — top-N by total time, by mean time,
   regressions after a deploy.
5. `integrating-with-explain-workflows` — going from a queryid
   to a plan; how to recover the actual query text.
6. `cost-and-caveats` — overhead; query normalization edge cases
   (dynamic SQL, `IN` lists, JSONB path expressions).

### 3. E2 pg_trgm — lessons

Target **7 lessons**:

1. `what-pg-trgm-is-for` — fuzzy matching, typo tolerance,
   similarity search; how it differs from FTS and when you
   need both.
2. `similarity-and-word-similarity` — `similarity()`,
   `word_similarity()`, thresholds, the `%` operator.
3. `gin-and-gist-on-trigrams` — choosing the index type; query
   patterns each supports.
4. `combining-fts-and-trigrams` — a hybrid search pattern: FTS
   for precision, trigrams for typo tolerance.
5. `deduplication-candidates` — using similarity to find likely-
   duplicate customer rows.
6. `support-ui-search` — the classic "type-ahead over a support
   article store" pattern.
7. `cost-and-caveats` — index size; write overhead; when
   dedicated search engines (Meilisearch, OpenSearch) are the
   right next step — explicit "not yet" thresholds.

### 4. Exercises

Per lesson (E1+E2): 2A + 2B + 2C + 2D. ~104 exercises.

Critical drills:

- E1: Level C — "given pg_stat_statements output fixture,
  identify the top regression after a fictional deploy, produce
  a triage report."
- E1: Level D — "a pg_stat_statements integration that is not
  showing the worst queries because `pg_stat_statements.max`
  is too low and the stats ring is being cycled."
- E2: Level C — dedupe candidate customer rows in ecommerce; use
  `word_similarity()` with a sensible threshold; justify the
  threshold.
- E2: Level D — a GIN-trigram index is present but not used
  because the query uses `LIKE 'prefix%'` which a btree would
  serve better; learner diagnoses and proposes a btree on the
  expression.
